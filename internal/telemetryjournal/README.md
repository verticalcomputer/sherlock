# Telemetry journal and ownership retirement

This package stores immutable telemetry ownership independently from Sherlock's collector-work and diagnostic leases. A verifier must check the strict shared telemetry protocol, signature, current enrollment and revocation before every admission, including matching replay. A configured session verifier must do the same for signed lifecycle messages.

A node returns internal `NODE` durability only. It retains a sealed body until the matching `GATEWAY` receipt or a durable explicit local loss. The gateway retains bodies until the matching `CLOUD` receipt bound to its own original gateway receipt. An acknowledgement is committed before unlink. Matching key/digest replay returns the original receipt; conflicting replay fails. Authorization is checked first.

Local journal schema 3 stores scope/source/session identities once, compact receipt facts, and role-specific ownership-retirement proofs. Initialized schema1/schema2 journals are rejected and preserved; there is no implicit migration or reset. Earlier schema2 foundation acceptance is historical; the [protocol reference](../../docs/reference/telemetry/protocol.md) describes current compatibility. Missing identity/database, malformed persisted ownership/loss facts, unknown orphan payloads or corruption fail closed. Startup validates receipts in pages of 256 and source-loss facts in pages of 256 before recovery can retire payloads. Loss ordinals are durable and monotonic. `Lookup` distinguishes proven absence from corruption or known transferred/lost ownership; only `ErrNotFound` authorizes missing-allocation recovery.

Default node allocation is 256 MiB:176 MiB data,64 MiB metadata,8 MiB loss/contact and 8 MiB staging. Default gateway allocation per node is 512 MiB:384 MiB data,64 MiB metadata,32 MiB loss/contact and 32 MiB staging. Gateway aggregate allocation is 8 GiB:7 GiB data,512 MiB metadata,256 MiB loss/contact and 256 MiB staging. Gateway service construction must require the aggregate budget. Admission and mutation hold its exclusive lease through file and SQL commits. Allocated blocks, directories, SQLite/WAL, immutable loss/session facts and allocator files count; incoming files are rounded to the reported filesystem allocation unit. Units outside 512–65,536 bytes refuse admission. Contact bodies use at most half the node control reserve; explicit local-loss facts also have a bounded logical allowance within their metadata allocation. A 1 GiB free-space reserve is the default. SQL/WAL growth has preflight headroom; exhaustive filesystem ENOSPC/crash and runtime RSS qualification remain separate gates.

`SPOOL_EXPIRED` and `SPOOL_OVERFLOW` describe local node discard, not proof of remote absence. They may overlap already received gateway evidence after a lost acknowledgement. The immutable loss fact remains, and actual received evidence takes precedence for coverage. New `SOURCE_LOSS` or `STORAGE_CORRUPTION` cannot contradict received evidence. A batch cannot declare itself lost. Later historical fills retain earlier loss history. Unknown loss times/counts remain unknown.

Known older sessions may replay historical bytes. Process restart reuses its session; a new boot or deliberate active-key rotation uses exactly the next epoch. At most 8 unretired sessions are admitted. Finalization records the terminal sequence and explicit gaps; it does not retire ownership or assert complete coverage. The drain chooses one newest ingress for three oldest ingress data turns, with every fifth turn reserved for control/loss.

The [ownership-retirement contract](../../docs/reference/telemetry/ownership-retirement.md) defines signed node prefix releases, gateway admission, cloud PREPARED, durable gateway commit, cloud FINAL, node allocator compaction, and signed node completion with its cloud receipt. A release spans at most 4,096 allocated positions with at most 256 selected batch facts and 256 selected loss facts; its wire envelope is at most 200 KiB. Unknown allocation holes block release. Selected facts prove ownership disposition, never complete sensor measurements. Node allocator callbacks are idempotent and must fsync/rename/directory-sync without nested Queue calls. The exact final proof is stored before invoking a callback, so restart can repeat safely after callback success but SQL failure.

The gateway retains exact receipts for at least seven days after the later of its durable cloud acknowledgement and the cloud receipt time, and prunes only after exact signed node completion is durably acknowledged. Gateway-owned bytes have no TTL deletion. `LookupOwnership` distinguishes exact entries (including original local-loss facts), known transferred ranges, explicit loss ranges and expired receipts. Sparse range records bind the exact immutable session ID; absent originals and previously unknown intersecting loss facts cannot cross a sealed range. A reclaimed carrier's exact original receipt and matching upstream acknowledgement preserve every contained source-loss handoff, including facts about an older session that releases later.

Only contiguous finalized sessions with a completed terminal allocation prefix can advance the retired epoch base. Gateway compaction additionally requires its exact cloud FINALIZE handoff. A cloud FINAL or FINALIZE/Covered flag alone grants no reclamation. At most eight unfinished releases and eight recent completed releases per session are retained; sparse disposition ranges are capped at 256 per kind/session, retained receipt-session identities and historical public keys at 4,096 each. Physical category limits may backpressure before these independent ceilings are all reached. Historical public keys establish signature integrity only, never current authorization. Retirement-enabled queues require reviewed public keys. A newly rotated signer must be installed through a reviewed restart/reopen before admission; matching historical replay still checks current grant/revocation first.

Focused fixtures exercise handshake/replay, callback crash/restart, exact seven-day pruning, ninth-session admission after retirement, FINALIZE-only gaps, carrier-first retirement, schema2 preservation, corrupt proof/identity/key refusal before payload mutation, and bounded physical admission. Exhaustive combined-ceiling capacity, ENOSPC/filesystem crash matrices, runtime RSS, client overhead, native hardware coverage, exact release review and live acceptance remain separate gates. Source publication does not close those gates. The opt-in weekly test validates 60,480 synthetic compact transferred receipts with worst-length IDs/16 sources against a 32 MiB physical target under default limits; sampled Go heap is not runtime RSS.
